# ADR-013：内存模型临时方案（Q-01）

- 状态：待验证（临时方案，不冻结）
- 日期：2026-10-25
- 来源：P0 决策，对应 `docs/规范/01-语言规范-V0.1.md` §14 与 `docs/规范/00-设计文档索引与决策总表.md` Q-01

## 背景

ADR-009 只规定了方向（可预测、易理解、不引入 GC），没有具体机制。P1 的解释执行器与前端需要一个确定的内存假设，否则无法写出值语义与状态更新的实现。

## 备选方案

- 方案 A：值类型 + 引用计数的不可变共享值，禁止可变引用（01 §14 的暂定方案）。优点：状态图无循环引用，不需要回收器，语义简单。缺点：大集合修改需要复制或结构共享，可能影响列表性能。
- 方案 B：所有权与借用（类似 Rust）。优点：零运行时开销。缺点：AI 生成代码的正确率风险高，与"易理解"目标冲突，实现成本大。
- 方案 C：追踪式垃圾回收。被 ADR-009 明确排除。

## 决策

在 P1 期间采用方案 A 作为工作假设。P1 的实现必须通过接口隔离，使内存策略可以替换。

## 理由

方案 A 与 01 规范的语义（不可变绑定、无可变引用、状态只能经 `action` 修改）直接对应，能让 P1 尽快产出可测试的前端。它的性能代价未知，因此必须用实验验证，而不是直接承诺。

## 后果与影响范围

- 01 §14 保持"暂定"标记，不得被视为冻结规范。
- P1 的集合类型必须隐藏底层表示，以便后续改为结构共享或其他策略。
- 任何依赖引用计数语义的对外行为（例如释放时机的可观察性）在规范冻结前不得承诺。

## 修改条件

满足任一条件时必须重新评估并取代本 ADR：

1. EXP-001 或 B3 的列表性能（滚动帧时间、布局计算时间）不满足 05 文档的探索目标，且原因被证明与引用计数有关。
2. P1 解释执行器中，集合复制导致的开销超过可接受范围，且无法通过结构共享消除。
3. 出现必须依赖可变引用才能实现的功能需求（例如 UI 组件的大量就地更新）。
