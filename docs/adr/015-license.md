# ADR-015：项目许可证

- 状态：已确定（Aster 自有代码采用 MIT）；LICENSE 文件待确认版权持有人与第三方依赖审查后创建
- 日期：2026-10-25（修订）
- 来源：P0 决策，对应 `docs/规范/06-仓库-代码规范-贡献指南.md` §8

## 决策

- Aster 自有代码（编译器、CLI、UI 模型、标准库、官方组件）采用 **MIT** 许可证。
- 第三方依赖保留各自的许可证，逐项审查，不随 Aster 重新授权。
- `Cargo.toml` 的 `license` 字段为 `MIT`。

此前的候选 MIT OR Apache-2.0 被放弃。代价是：MIT 没有 Apache-2.0 那样的明确专利授权条款。这是有意接受的取舍，记录在此，以便将来重新评估。

## 备选方案（已比较）

- MIT：简单，兼容性广，没有明确的专利授权条款。（采用）
- MIT OR Apache-2.0：使用者可任选其一，保留 Apache-2.0 的专利条款。（未采用，由项目维护者决定）
- Apache-2.0：专利条款明确，但与部分 MIT 项目的组合习惯不同。（未采用）

## 第三方依赖与 Slint 的许可证（核实于 2026-10-25）

Aster 代码的许可证与依赖的许可证是两件事。

| 依赖 | 许可证 | 状态 |
|---|---|---|
| serde、serde_json、toml、pollster | MIT 或 Apache-2.0（待逐项确认） | 待审查 |
| slint、slint-interpreter、slint-build 1.18.1 | `GPL-3.0-only OR LicenseRef-Slint-Royalty-free-2.0 OR LicenseRef-Slint-Software-3.0` | 原型使用，正式分发未确认 |

Slint 的官方条款（slint.dev/terms-and-conditions）要点：

- **Royalty-Free 2.0**：允许把 Slint 作为桌面、移动应用的一部分分发，可以用 MIT 或 Apache-2.0 发布自己的代码。条件是署名（在 About 界面显示 AboutSlint 组件，或在公开下载页面显示 Slint 徽章）。不得用于嵌入式系统。不得单独分发 Slint 而不集成进应用。
- **禁止分发"暴露 Slint API"的应用**：Royalty-Free 条款明确禁止分发向外暴露 Slint API（全部或部分）的应用。
- **Slint Software License 3.0（付费）**：要求为参与设计、开发、测试应用的每个人购买席位。
- **GPL-3.0 分支**：用其分发完整应用时，应用整体须按 GPLv3 授权，与 MIT 项目不兼容。

Aster 的特殊情况：Aster 生成 `.slint` 源码并通过 Slint 解释器加载。Aster 工具链本身也会分发给开发者。普通应用的授权说明不足以证明这些场景合规。在正式分发工具链或生成的应用之前，必须确认以下场景：

1. 工具链分发（Slint 作为工具链的一部分交付给开发者）；
2. 生成代码（Aster 生成的 `.slint` 是否属于"暴露 API"）；
3. 运行时依赖（解释器是否作为应用的一部分分发）；
4. API 暴露（Aster 语言是否向用户暴露 Slint API）。

无法确认时，向 Slint 维护方取得书面答复，或比较其他后端与商业授权方案。

**当前结论**：不把 Slint 固化为唯一正式后端；原型阶段继续使用，并在每次依赖变更时记录版本与许可证。

## 尚未完成的前置条件

创建 `LICENSE` 之前必须完成：

1. **版权持有人。** 需要项目维护者确认版权署名（例如个人或组织名称）。
2. **依赖审查。** 第三方依赖的许可证逐项核对（见上表），并在 `NOTICE` 或 `cargo-deny` 配置中登记。
3. **Slint 场景确认。** 见上文四个场景，未确认前不发布 Aster 工具链或生成应用。
4. **贡献者授权规则。** DCO 或 CLA（06 §8.2）。

在前置条件完成前，不创建 `LICENSE`，不发布任何包或发行版本。

## 修改条件

- Slint 场景确认结果不符合条款：更换后端或取得商业授权，并更新本 ADR。
- 维护者改变许可证选择（例如改回双许可）：修订本 ADR，并同步 `Cargo.toml`。
