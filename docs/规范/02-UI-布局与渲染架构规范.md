# Aster UI、布局与渲染架构规范

**文档编号：** ASTER-UI-001
**版本：** V0.1 Draft
**状态：** 草案。布局语义与组件模型待 UI Spike（技术验证阶段）验证后冻结。
**依赖：** ASTER-ARCH-001（ADR-004 至 ADR-007）、01 语言规范、03 IR 规范

---

## 1. 范围与目标

本规范定义：

1. 界面描述的结构语法与组件模型；
2. 布局的语义、测量与排布规则，以及布局冲突的判定；
3. 样式与设计令牌的规则；
4. 数据绑定、事件与线程模型在界面中的表现；
5. 文字、输入法、无障碍的最低要求；
6. 渲染抽象层的边界；
7. V0.1 组件集合与性能约束。

核心要求来自基础设计文档的原则 3 与原则 4：界面设计能力不能退化，布局结果必须可观测、可解释。

## 2. 界面的三层划分

界面描述分为三层，每层有独立的语法块，但共享同一组件树：

| 层 | 语法 | 职责 |
|---|---|---|
| 结构 | 组件树（`Column { ... }`） | 组件、内容、插槽、数据绑定、事件 |
| 布局 | 组件上的尺寸与排布属性 | 尺寸、间距、对齐、约束、溢出 |
| 视觉 | `design` 块、`style` 块、组件上的视觉属性 | 颜色、字体、圆角、阴影、动画、主题 |

规则：修改视觉层不得改变布局结果；修改布局层不得改变颜色与字体。编译器对跨层的不当修改（例如在布局属性中写颜色）报告 `E4100`。

## 3. 组件模型

### 3.1 组件实例

```
Button("搜索") {
    id: search_button
    style: primary
}

on search_button.click {
    search_files(state.query)             // 事件语法见 §7.3
}
```

- 组件名以大写字母开头。
- 位置参数用于组件的"主内容"（如 `Text` 的文本、`Button` 的标签），每个组件最多一个位置参数。
- 属性写在花括号中，使用 `name: value` 格式，每行一个。
- 每个实例可以有 `id`。**同一窗口内 `id` 必须唯一**，否则报告 `E3100`。
- 没有写 `id` 的实例由编译器根据组件树路径生成稳定 ID（规则见 03 §3）。

### 3.2 组件定义

V0.1 不支持用户定义组件。所有组件由标准组件库提供，并满足本规范 §3.3 的元数据要求。用户自定义组件属于后续版本，并需要通过 RFC 设计插槽、状态与样式作用域。

### 3.3 组件元数据（机器可读）

每个标准组件必须声明以下元数据，并以 JSON 形式导出（协议见 03）：

- `name`、`version`、`intent`（一句话用途）；
- `props`：名称、类型、取值范围、默认值；
- `slots`：可接收的子元素类型与数量限制；
- `states`：如 normal、hover、pressed、disabled、focused、error；
- `layout_rules`：尺寸约束、溢出行为、最小尺寸；
- `events`：名称、参数类型；
- `accessibility`：角色、标签来源、键盘行为；
- `examples`：推荐用法与一个反例。

## 4. 单位与坐标

- 布局单位为 **逻辑像素 `dp`**。1 dp 在 DPI 为 96 的显示器上对应 1 物理像素，实际映射为 `physical = dp × scale`。
- 字体大小使用 `sp`（与系统文字缩放挂钩）。V0.1 中若未指定单位，字体大小默认按 `sp` 解释。
- 坐标原点位于父容器内容区左上角，x 向右、y 向下。
- 所有布局计算在逻辑像素中进行。物理像素舍入只发生在绘制前的最后一步，舍入规则必须在诊断中可查询。

## 5. 布局

### 5.1 尺寸描述

每个组件在每个轴向（宽、高）上有三个值：

| 属性 | 含义 |
|---|---|
| `width` / `height` | 首选尺寸：`240dp`、`fill`、`wrap`（默认） |
| `min_width` / `min_height` | 下限，默认 0 |
| `max_width` / `max_height` | 上限，默认无限 |

- `wrap`：尺寸等于内容所需尺寸。
- `fill`：占满父容器在该轴上分配给它的剩余空间。多个 `fill` 兄弟按 `weight` 均分（默认 `weight = 1`，写法 `fill(2)`）。
- 不允许负尺寸。`min > max` 为编译错误 `E4002`。

### 5.2 布局容器

| 容器 | 布局模式 | 关键属性 |
|---|---|---|
| `Column` / `Row` | 线性（Flex 语义） | `gap`、`padding`、`align`（交叉轴）、`justify`（主轴） |
| `Grid` | 网格 | `columns: [1fr, 240dp]`、`rows`、`gap`，子元素可用 `column`、`row`、`span` |
| `Stack` | 叠放 | 子元素在同一区域内叠放，按声明顺序，后声明在上 |
| `Scroll` | 滚动视口 | `direction`（vertical / horizontal / both），内容超出时可滚动 |
| `Splitter` | 可拖拽分割 | 两个子元素，`ratio` 或 `min_size` |
| `Canvas` | 绝对定位 | 子元素使用 `x`、`y`，只允许在 `Canvas` 内使用 |

普通界面优先使用 `Column`、`Row`、`Grid`。`Canvas` 的绝对坐标是允许的，但在非 `Canvas` 容器中使用 `x`、`y` 属性时，编译器报告警告 `W4010`。

### 5.3 测量与排布

布局分为两遍：

1. **测量（自底向上）：** 每个节点根据内容与约束返回 `preferred` 尺寸与 `min` 尺寸。
2. **排布（自顶向下）：** 父节点根据可用空间为每个子节点分配最终矩形。

分配规则（Column/Row，以主轴为例）：

1. 固定尺寸与 `wrap` 子元素先取其 preferred 尺寸；
2. 剩余空间（扣除 gap 与 padding）分配给 `fill` 子元素，按 weight 比例；
3. 若分配结果小于子元素的 `min`，则取 `min`，并标记该子元素为"被压缩到下限"；
4. 若所有子元素的 `min` 之和超过可用空间，则判定为**布局冲突**（见 §5.4）；
5. 若超过 `max`，则截断到 `max`，剩余空间按规则 2 再分配给未截断的兄弟。

### 5.4 布局冲突与溢出

布局引擎必须能解释结果。以下情形产生结构化诊断：

| 诊断 | 条件 | 默认级别 |
|---|---|---|
| `LAYOUT_CONFLICT` | 子元素 `min` 之和超过父容器可用空间 | error |
| `LAYOUT_OVERFLOW` | 内容超出父容器且父容器未设置 `Scroll` | error |
| `LAYOUT_CLIPPED` | 子元素被父容器裁切 | warning |
| `LAYOUT_OVERLAP` | 非 `Stack`、非 `Canvas` 的兄弟元素矩形相交 | error |
| `LAYOUT_UNBOUNDED_FILL` | `fill` 元素的父容器在该轴上为 `wrap` | error |

每条诊断必须包含：组件 ID、属性名、源位置、实际值、可用值、差值、来源（哪个约束导致）。诊断格式见 03 §4。

示例（与 03 文档中的格式一致）：

```json
{
  "code": "LAYOUT_CONFLICT",
  "severity": "error",
  "component": "sidebar",
  "property": "min_width",
  "source": "app/main.as:12:9",
  "available": 720,
  "required": 736,
  "overflow": 16,
  "constraints": [
    {"component": "sidebar", "property": "min_width", "value": 240},
    {"component": "content", "property": "min_width", "value": 400},
    {"component": "root", "property": "padding", "value": 96}
  ],
  "suggestions": [
    "reduce padding on root",
    "lower content.min_width",
    "allow sidebar to collapse"
  ]
}
```

### 5.5 锚点与约束（V0.1 有限支持）

- V0.1 支持 `align: center | start | end | stretch` 与 `anchor: left | right | top | bottom` 的组合，用于在 `Stack` 内定位。
- 完整的约束求解器（如 Cassowary 类算法）不在 V0.1 范围内。约束表达式限制为"相对父容器的边距"与"相对兄弟的间距"两类。

### 5.6 布局的确定性

同一输入（组件树、属性、窗口尺寸、DPI、字体度量）必须产生同一输出。布局引擎不得依赖遍历顺序以外的隐藏状态。字体度量缺失时使用回退字体，并在诊断中标注 `FONT_FALLBACK`。

## 6. 样式与设计令牌

### 6.1 设计块

```
design Modern {
    colors {
        background: #F7F8FA
        surface: #FFFFFF
        text: #20242C
        accent: #635BFF
    }
    spacing { small: 8dp  medium: 16dp  large: 24dp }
    radius { control: 8dp  card: 14dp }
    typography { body: 14sp  heading: 24sp }
    motion { quick: 120ms  normal: 200ms }
}
```

- 令牌必须有类型（`color`、`length`、`font_size`、`duration`），由所在分组决定。
- 组件属性引用令牌使用 `token.<分组>.<名称>`，例如 `color: token.colors.text`。
- 引用未定义令牌报告 `E4201`。
- 令牌类型不匹配（如把 `duration` 用于 `color`）报告 `E4202`。

### 6.2 命名样式

```
style heading {
    font_size: token.typography.heading
    weight: bold
    color: token.colors.text
}
```

组件通过 `style: heading` 使用命名样式。

### 6.3 样式优先级

**V0.1 不实现 CSS 式的层叠与选择器。** 样式值按以下顺序决定，后者覆盖前者，且优先级在编译期确定：

1. 组件内建默认值；
2. 当前主题（`theme`）中的令牌映射；
3. 命名样式（`style`）；
4. 组件实例上的显式属性。

- 不存在选择器，不存在全局样式覆盖，不存在"按后代元素匹配"的规则。
- 不存在隐式继承。需要继承的值（如字体）必须通过显式的 `style` 或令牌传递。
- 编译器与检查器可以对任一属性报告"值来自哪一层"（`style_source`），这是 Q-06 所需的可追踪性。

### 6.4 主题

```
theme light { bind Modern; colors.background: #F7F8FA }
theme dark  { bind Modern; colors.background: #15171C }
```

- 主题切换只修改令牌映射，不修改组件结构。
- 主题由状态选择：`theme: state.theme`。
- 系统浅色/深色切换由平台事件驱动，映射为一次状态更新。

### 6.5 动画

- V0.1 只支持属性过渡（`transition: opacity quick`）与显示/隐藏动画。
- 动画不得改变布局结果（布局使用动画前的目标值，视觉使用过渡中的插值）。该要求用于避免动画期间的布局抖动。
- 复杂关键帧动画推迟到 V0.2 之后。

## 7. 结构控制与数据绑定

### 7.1 条件与循环

```
Column {
    if state.loading {
        Progress()
    } else {
        for file in state.files {
            Row(key: file.path) {
                Text(file.name)
                Text(file.size_text())
            }
        }
    }
}
```

- 循环必须声明 `key`，用于增量更新与状态保持。缺失时报告 `E4300`。
- `if` 与 `for` 的条件和集合表达式只读，不得有副作用。
- 列表元素超过 1000 项时，`for` 循环必须由 `List` 或 `Scroll` 包裹以启用虚拟化（见 §12）。否则报告警告 `W4300`。

### 7.2 绑定

| 语法 | 方向 | 说明 |
|---|---|---|
| `text: state.title` | 单向 | 状态变化时更新显示 |
| `bind value: state.query` | 双向 | 用户输入写回状态，必须通过 `action` |

- 双向绑定的写回不直接修改状态，而是调用该属性对应的内建 `action`（如 `TextInput` 的 `on_change`）。编译器在绑定中检查状态字段类型与组件属性类型是否一致。
- 绑定表达式中的函数只能是 `fn`，不得是 `action` 或 `async fn`。

### 7.3 事件

```
on search_button.click {
    search_files(state.query)
}
```

- 事件块只能包含 `action` 调用或直接的状态赋值（直接赋值视为隐式 `action`，编译器要求放入具名 `action` 以便追踪）。
- 事件参数由组件元数据定义，例如 `TextInput.submit(text: String)`。

## 8. 线程与生命周期

- 所有界面对象只在 UI 线程访问。
- `action` 在 UI 线程执行；`async fn` 在后台执行器中执行，结束后在 UI 线程恢复。
- 视图创建时注册其绑定与事件；视图销毁时取消其拥有的异步任务，并释放绑定。
- 状态更新导致的重绘在一帧内合并，不得在 `action` 中同步触发重绘。

## 9. 文字、输入法与国际化

这些要求是 V0.1 的最低标准，不是后期功能（见基础设计文档原则 3 与 ADR-007）。

| 能力 | 最低要求 |
|---|---|
| 字体回退 | 按字符集分级回退；中文必须有回退字体；缺字时显示替代字形并产生 `FONT_FALLBACK` 诊断 |
| 文字排版 | 支持中英混排、换行、双向文本的基本规则（RTL 可以在 V0.2 完善） |
| 输入法 | 支持组合文本（preedit）、候选窗口定位、提交（commit）三个阶段 |
| 编辑操作 | 光标移动、选择、删除、复制、粘贴、撤销 |
| 本地化 | 所有界面文字通过消息键引用，支持语言包切换（见 §9.1） |
| 高 DPI | 字体与控件随 scale 缩放，不出现模糊或错位 |

### 9.1 本地化与语言包

GUI 界面文字必须可本地化。V0.1 即支持语言包的加载与运行时切换，不以"单语言"作为临时方案，因为后期引入本地化会迫使所有界面字符串与布局重写。

**源语言与默认语言：**

- 源文本（消息键的默认值）使用英语。`en` 是强制存在的语言包，其他语言包缺失某个键时回退到 `en`。
- 清单中声明默认语言与支持的语言列表（见 04 §5.1 的 `[i18n]` 段）。

**消息键与语言包：**

- 界面文字在源码中通过消息键引用，不得在组件的 `Text` 中直接写中文或其他非英语字符串。

  ```
  Text(tr("search.button"))
  Button(tr("toolbar.new_folder"))
  ```

- 语言包是纯数据文件，位于 `locales/<BCP 47 标签>.toml`，例如 `locales/en.toml`、`locales/zh-CN.toml`。

  ```toml
  # locales/zh-CN.toml
  [search]
  button = "搜索"
  placeholder = "搜索文件…"

  [files]
  count = "共 {count} 个文件"
  ```

- 占位符使用 `{name}` 形式，名称必须与源语言包一致。占位符不一致时产生诊断 `I18N_PLACEHOLDER_MISMATCH`。
- 语言包不得包含可执行内容。它只是字符串数据，不能调用函数，也不能访问资源。

**语言切换：**

- 当前语言是状态字段（如 `state.locale`），由 `action` 修改。切换后，所有依赖 `tr()` 的绑定在下一帧更新，不需要重启应用。
- 应用可以跟随系统语言（平台事件映射为一次状态更新）。
- 查找顺序：`当前语言 → 语言标签的父级（如 zh-CN → zh）→ en`。

**编译期与运行期检查：**

| 诊断 | 条件 | 级别 |
|---|---|---|
| `W4500` | 组件中直接使用字符串字面量作为可见文字（未经 `tr()`） | warning |
| `I18N_MISSING_KEY` | `tr()` 引用的键在 `en` 中不存在 | error |
| `I18N_MISSING_TRANSLATION` | 某个支持的语言缺少该键 | warning（运行时回退到 `en`） |
| `I18N_PLACEHOLDER_MISMATCH` | 译文占位符与源文本不一致 | error |
| `I18N_UNUSED_KEY` | 语言包中的键没有被引用 | info |

**布局要求：**

- 译文通常比英语更长或更短。布局必须能容纳目标语言的文本，因此每个语言包都要有布局测试。
- 必须提供**伪本地化（pseudo-locale）**：自动将文字替换为变长、带重音的字符串，用于在不翻译的情况下发现布局溢出。伪本地化是 `aster test` 的标准运行模式之一。
- 文字溢出由 §5.4 的布局诊断报告，不因本地化而豁免。

**无障碍与格式：**

- 无障碍标签（§10）同样通过消息键提供，与可见文字使用同一套语言包。
- 数字、日期、时间的格式化由标准库 `i18n` 模块按当前语言完成，不得在应用代码中手动拼接。

**V0.1 范围：**

- 包含：语言包加载、回退链、占位符、运行时切换、`W4500`、`I18N_MISSING_KEY`、`I18N_PLACEHOLDER_MISMATCH`、伪本地化、中文与英文两个语言包的示例。
- 不包含（推迟到 V0.2）：复数规则（CLDR 复数类别）、RTL 布局镜像、语境性语法变化。推迟项必须在语言包格式中预留位置，不得改变已发布的键结构。

**字体与语言包的关系：** 每个语言包所需的字符集由字体回退链覆盖（见本节前文）。缺少字形的语言包在加载时产生 `FONT_FALLBACK` 诊断。

中文输入法验证是 P2 出口门禁 G2 的条件之一，见 07 文档。

## 10. 无障碍

- 每个交互组件必须声明角色（role）与标签（label）。`Button` 的标签默认来自位置参数。
- 焦点顺序默认与组件树的遍历顺序一致；`focus_order` 属性可以覆盖，但必须在诊断中可查询。
- 所有交互组件必须可以通过键盘完成基本操作（Tab 切换、Enter/Space 激活）。
- 颜色对比度：文本与背景的对比度低于 WCAG AA 时产生警告 `W4400`。
- 无障碍树由平台适配层映射到系统无障碍接口。

### 11.6 平台能力声明（ADR-016）

- 共享 UI 模型不得依赖具体平台。窗口菜单、系统托盘、多窗口、原生文件对话框、快捷键等能力只能通过**能力（capability）**引用。
- 每个平台后端必须声明其能力集合（例如 `multi_window`、`native_file_dialog`、`system_tray`、`touch_input`）。
- 共享模型使用了某项能力，而目标平台未声明该能力时，校验器必须产生诊断（建议码 `E4600`，待码表登记），不得在运行时静默忽略。
- 移动端的生命周期（后台、暂停、恢复）由平台适配层转换为共享的生命周期事件；共享模型不假设窗口常驻。

## 11. 渲染抽象层

### 11.1 管线

```
UI IR ──► 布局结果 ──► 显示列表（Display List）──► 渲染后端 ──► 屏幕
```

- **显示列表**是渲染层的唯一输入。它是一组有序的绘制命令，不包含任何组件语义。
- 布局层与渲染层之间只通过显示列表和布局结果（矩形、裁切区域）通信。

### 11.2 绘制命令（V0.1 集合）

| 命令 | 参数 |
|---|---|
| `Rect` | 矩形、填充、描边 |
| `RoundRect` | 矩形、圆角半径 |
| `TextRun` | 文本、字体、位置、颜色、已排版字形 |
| `Image` | 资源句柄、目标矩形、采样方式 |
| `PushClip` / `PopClip` | 裁切矩形 |
| `PushOpacity` / `PopOpacity` | 不透明度 |
| `Shadow` | 矩形、偏移、模糊、颜色 |

渐变、变换、复杂路径属于 V0.2 之后的扩展，在接口中预留，但 V0.1 后端可以不实现。

### 11.3 后端接口

后端必须实现以下操作（语义定义，具体 Rust trait 在实现阶段确定）：

- `begin_frame(size, scale)` / `end_frame()`
- `submit(commands)`：提交显示列表的完整或增量版本
- `measure_text(text, font) -> Metrics`：字体度量（布局需要）
- `load_font(source) -> FontHandle` / `release_font(handle)`
- `capabilities() -> Capabilities`：报告支持的命令与像素格式

布局层只调用 `measure_text`，不调用其他绘图接口。

### 11.4 脏区与局部重绘

- 布局结果或显示列表的变化以组件为粒度标记为"脏"。
- 后端可以只重绘脏区域；全量重绘是默认回退。
- 脏区信息是诊断输出的一部分（"本帧重绘了哪些组件"），用于性能分析。

### 11.5 后端候选与隔离

| 候选 | 角色 | 状态 |
|---|---|---|
| Slint | 对照基线（EXP-003）；Spike 中的临时后端 | 只用于验证，不作为长期承诺 |
| Skia | 候选正式渲染后端 | 待 EXP-001 测量包体积 |
| WGPU 生态 | 候选 GPU 后端 | 待验证文字与软件回退 |
| 平台原生 API | 对特定组件（菜单、对话框）使用 | 不用于通用绘制 |

UI 语义层不得直接引用任何后端类型。这一约束由 `ui/` 与 `backend/` 的依赖方向保证（见 06 文档）。

## 12. V0.1 组件集合与性能约束

### 12.1 V0.1 组件（15 个）

| 分类 | 组件 |
|---|---|
| 窗口与容器 | `Window`、`Column`、`Row`、`Grid`、`Stack`、`Scroll`、`Splitter` |
| 显示 | `Text`、`Icon`、`Divider` |
| 操作 | `Button`、`Toolbar` |
| 输入 | `TextInput`、`Checkbox` |
| 数据 | `List` |

其余组件（Image、Tabs、Table、Tree、Dialog、Chart 等）属于 V0.2 或之后。基础设计文档中约 30 个基础组件的规划作为长期目标保留。

### 12.2 性能约束（探索目标，待基线验证）

以下数值是 05 文档中测量的目标，不是承诺：

- 单次状态更新到屏幕刷新的延迟：在常规界面中不超过一个帧周期（60 Hz 下约 16.7 ms）。
- 1000 行 `List` 滚动：不做全量布局，只布局可见区域加缓冲行。
- 窗口缩放：布局重算不产生可见的卡顿。

### 12.3 虚拟化

- `List` 默认虚拟化。只测量与绘制可见行及少量缓冲行。
- 虚拟化不得改变布局结果（可见行的位置与全量布局一致）。该性质必须有测试覆盖。

## 13. 界面相关的诊断码

| 码 | 含义 |
|---|---|
| `E3100` | 窗口内组件 ID 重复 |
| `E4002` | 尺寸下限大于上限 |
| `E4100` | 视觉属性出现在布局层，或反之 |
| `E4201` | 引用未定义令牌 |
| `E4202` | 令牌类型不匹配 |
| `E4300` | 循环缺少 `key` |
| `W4010` | 非 `Canvas` 中使用绝对坐标 |
| `W4300` | 大列表未虚拟化 |
| `W4400` | 文字对比度不足 |
| `LAYOUT_CONFLICT` 等 | 见 §5.4 |
