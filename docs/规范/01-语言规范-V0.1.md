# Aster 语言规范 V0.1

**文档编号：** ASTER-LANG-001
**版本：** V0.1 Draft
**状态：** 草案。未冻结。
**依赖：** ASTER-ARCH-001（ADR-001/002/009）、ASTER-INDEX-001

---

## 1. 范围

本规范定义 Aster V0.1 的源语法、基本类型、声明、控制流、错误处理、状态与异步的语义。

本规范**不**定义：

- 界面布局与样式的详细语义（见 02）。
- 中间表示、诊断协议与 AI 接口（见 03）。
- 包、权限、插件（见 04）。
- 代码生成后端（ADR-003，待实验）。

V0.1 的目标是让一个小型桌面程序可以被编译、运行和诊断，而不是覆盖语言的全部设想。凡未列入本文的语法一律视为无效，编译器必须报告 `E1000`（未支持的语法）。

## 2. 词法与基本结构

### 2.1 源文件

- 源文件使用 UTF-8 编码，扩展名为 `.as`。
- 一个文件是一个模块。模块路径由目录结构决定。
- 语句以换行分隔，**不使用分号**。
- 块使用花括号 `{ }`。
- 注释：`// 单行注释`，`/// 文档注释`（作用于下一个声明）。V0.1 不支持块注释。

### 2.2 标识符与关键字

- 标识符以 ASCII 字母或 `_` 开头，后接 ASCII 字母、数字或 `_`。
- 字符串内容可以使用任意 Unicode 字符，包括中文。
- 标识符中**不允许**使用非 ASCII 字符。这样做是为了减少工具链与 AI 对符号的歧义，界面中的非英语显示文字由本地化语言包承担（见 02 §9.1）。

V0.1 关键字：

```
app window state action fn async await struct enum
let var if else match for in while break continue return
true false None Some Ok Err pub use on self
```

### 2.3 字面量

| 类别 | 示例 | 说明 |
|---|---|---|
| 整数 | `42`、`-7`、`1_000` | 64 位有符号，下划线仅用于分隔 |
| 浮点数 | `3.14`、`0.5` | 64 位 IEEE 754，必须有小数点 |
| 布尔 | `true`、`false` | |
| 字符串 | `"hello"`、`"第一行\n第二行"` | 支持 `\n \t \r \" \\ \u{XXXX}` 转义 |
| 长度 | `240dp` | 逻辑像素，见 02 §4。仅在 UI 属性中使用 |

V0.1 不支持字符串插值。需要拼接时使用 `text.format`（见 §12）。

## 3. 类型

### 3.1 内建类型

| 类型 | 说明 |
|---|---|
| `Int` | 64 位有符号整数，溢出时产生运行时错误并终止（不回绕） |
| `Float` | 64 位浮点数 |
| `Bool` | |
| `String` | UTF-8 不可变字符串 |
| `Unit` | 无返回值，写作 `()` |
| `Dp` | 逻辑像素长度，仅用于 UI 属性 |
| `Option<T>` | `Some(v)` 或 `None` |
| `Result<T, E>` | `Ok(v)` 或 `Err(e)` |
| `List<T>` | 有序序列 |
| `Map<K, V>` | 键值映射，`K` 必须是 `String`、`Int` 或枚举 |

### 3.2 用户类型

```
struct File {
    name: String
    size: Int
    modified: Int
}

enum FileError {
    NotFound(path: String)
    Denied(path: String)
    Io(message: String)
}
```

- 结构体字段全部为公开，V0.1 不支持字段级可见性。
- 枚举变体可携带命名字段。
- 不支持继承、重载与子类型。

### 3.3 类型规则

- **无空指针。** 不存在 `null`。缺失值只能用 `Option<T>` 表达。
- **无隐式转换。** `Int` 与 `Float` 之间的运算必须显式调用 `to_float()` 或 `to_int()`。`Dp` 与 `Int` 之间同样必须显式转换。
- **泛型仅限内建容器。** V0.1 不允许用户定义泛型函数或泛型类型。
- **类型推断仅限局部变量。** 函数签名、结构体字段、状态字段必须写明类型。

## 4. 声明与绑定

```
let name = "Aster"            // 不可变绑定，类型推断为 String
let count: Int = 0            // 显式类型
var total = 0                 // 可变绑定
total = total + 1
```

- `let` 绑定不可重新赋值。
- `var` 绑定可重新赋值。`await` 挂起与恢复不改变绑定的可变性，但同一 `action` 中跨 `await` 使用的状态值须按 §9 重新读取。
- 不允许遮蔽（shadowing）同一作用域中的名称。同名声明在内层作用域允许，但编译器发出警告 `W1001`。

## 5. 函数与错误处理

### 5.1 纯函数

```
fn add(a: Int, b: Int) -> Int {
    return a + b
}
```

- `fn` 声明的函数**不得**修改状态，不得调用 `async` 函数，不得访问 UI。
- 函数参数不可变，参数不得重新赋值。
- 函数必须写明返回类型。无返回值时返回类型为 `Unit`，可省略写法 `-> Unit`。

### 5.2 错误

- 可能失败的操作返回 `Result<T, E>`。
- `?` 运算符用于传播错误：仅允许在返回 `Result<_, E2>` 的函数中使用，且要求 `E` 可以无损转换为 `E2`。V0.1 中该转换只允许 `E == E2`，不做自动转换；需要转换时必须显式 `match`。
- 不存在异常机制。`panic` 只用于不可恢复的程序错误（如索引越界、整数溢出），运行时输出诊断并终止进程，V0.1 不允许捕获。

```
fn read_size(path: String) -> Result<Int, FileError> {
    let text = filesystem.read_text(path)?
    return Ok(text.length())
}
```

## 6. 控制流

```
if x > 0 {
    ...
} else {
    ...
}

match result {
    Ok(files) => state.files = files
    Err(error) => notify(error.message())
}

for file in state.files {
    ...
}

while count < 10 {
    count = count + 1
}
```

- `if` 条件必须是 `Bool`，不得使用整数作为条件。
- `match` 必须穷尽所有变体，缺失分支为编译错误 `E2301`。通配符 `_` 可以使用，但编译器对新增变体发出警告。
- `for` 仅支持遍历 `List`、`Map` 与区间 `0..n`（不含上界）。
- `while`、`break`、`continue` 可用，不提供标签跳转。
- 语句表达式的值不被使用时，编译器产生警告 `W1002`。

## 7. 运算符

| 类别 | 运算符 | 说明 |
|---|---|---|
| 算术 | `+ - * / %` | 只作用于同类型数值 |
| 比较 | `== != < <= > >=` | 同类型比较，`String` 按字节序（UTF-8） |
| 逻辑 | `&& \|\| !` | 短路求值 |
| 赋值 | `=` | 语句，不是表达式 |
| 访问 | `.` | 字段、方法 |
| 错误传播 | `?` | 见 §5.2 |

- 不提供位运算符（V0.1）。
- 不提供运算符重载。

## 8. 状态（State）

状态是应用中可观察的数据，由 `state` 声明。每个 `app` 只能有一个 `state` 块。

```
state FileState {
    query: String = ""
    files: List<File> = []
    selected: Option<File> = None
}
```

规则：

1. 状态字段必须有初始值。
2. 状态字段只能在 `action` 中修改（见 §9）。
3. 在 `fn`、`async fn` 或 UI 绑定表达式中写入状态，编译器报告 `E3001`。
4. 状态的读取不受限制，但 UI 绑定表达式只能读取，不能有副作用。

## 9. 动作（action）与事件

`action` 是唯一允许修改状态的函数。它总是在 UI 线程执行。

```
action search_files(query: String) {
    state.query = query
    state.files = []
    let result = await filesystem.search(query)
    match result {
        Ok(files) => state.files = files
        Err(error) => notify(error.message())
    }
}
```

- `action` 可以调用 `fn` 与 `async fn`。
- `action` 可以使用 `await`。`await` 之后，执行恢复到 UI 线程，状态可以被安全修改。
- 同一时刻，一个 `action` 的执行不会被另一个 `action` 打断，但 `await` 之间可以交错执行其他 `action`。编译器无法判断交错是否安全，因此 V0.1 要求：**同一 `action` 在 `await` 前后读取的状态，必须在使用前重新读取。**
- 事件绑定格式为 `on <组件ID>.<事件名>(参数) { ... }`，参数类型由组件定义决定（见 02）。事件处理块的内容必须是 `action` 调用或 `action` 体。

## 10. 异步

```
async fn search(query: String) -> Result<List<File>, FileError> {
    ...
}
```

- `async fn` 只能通过 `await` 调用。V0.1 不提供 `spawn`（后台启动而不等待），该能力推迟到后续版本。
- `async fn` 不得修改状态。
- 取消：窗口关闭或所属视图销毁时，尚未完成的异步任务被取消。任务在下一个挂起点（`await`）收到取消信号，并以 `Err(Cancelled)` 的形式结束。V0.1 中 `Cancelled` 是 `async` 模块预定义的错误类型。
- 阻塞式文件与网络 API 只能通过 `async` 版本调用；编译器对在 `action` 中调用同步 I/O 函数报告 `E3010`。

## 11. 模块与可见性

```
use std.filesystem
use std.text.format

pub fn is_hidden(name: String) -> Bool {
    return name.starts_with(".")
}
```

- `use` 导入模块，导入路径使用点号分隔。
- 默认不导出。`pub` 声明对外可见。
- 循环依赖为编译错误 `E2010`。
- 模块的物理位置由包清单决定（见 04 §5）。

## 12. V0.1 标准库子集

V0.1 只实现以下模块。其余模块属于后续版本，不得在 V0.1 项目中引用。

| 模块 | V0.1 包含内容 |
|---|---|
| `core` | 基本类型、`Option`、`Result`、断言 |
| `collections` | `List`、`Map` 的基本操作 |
| `text` | 长度、切分、前缀判断、`format` |
| `math` | 基本算术、`min`、`max`、`clamp` |
| `path` | 路径拼接、文件名、扩展名 |
| `filesystem` | 异步读取、写入、列目录（需权限，见 04） |
| `logging` | 分级日志 |
| `json` | 解析与序列化 |
| `time` | 时间戳、格式化（不含时区数据库） |
| `async` | `Cancelled`、`sleep` |
| `i18n` | 消息键查找（`tr`）、当前语言、语言包加载、数字与日期格式化（见 02 §9.1） |

`network`、`process`、`window`、`menu`、`dialog`、`clipboard`、`system_tray`、`notifications`、`keyboard`、`accessibility` 及 GUI 组件库不属于本规范的语言标准库，见 02 与后续规范。

## 13. 应用入口

```
app FileDesk {
    state FileState
    window main {
        // 界面结构见 02 文档
    }
}
```

- 每个程序有且只有一个 `app`。
- `app` 的名称与清单中的程序名一致（不同则编译错误 `E2020`）。
- V0.1 只允许一个 `window` 声明。多窗口为后续版本。

## 14. 内存模型（暂定）

本节是 **Q-01 的暂定方案**，不是冻结规范。

- 结构体与枚举是值类型。赋值时复制（编译器可优化为移动）。
- `List`、`Map`、`String` 是不可变共享值，底层使用引用计数。
- 语言不提供可变引用。这一限制使状态图中不会产生循环引用，因此不需要循环回收器。
- 对象的释放时机由引用计数确定，并且可以在诊断中查询。

该方案的代价是大集合的修改需要复制或结构共享。性能影响必须通过 EXP-001 与 05 文档的基准评估。若评估不通过，本节必须通过 ADR 修订。

## 15. 版本与兼容

- 语言版本写在清单的 `language` 字段中，格式为 `major.minor`。
- V0.x 阶段允许不兼容变更，但每次变更必须：
  1. 在变更日志中列出；
  2. 提供迁移工具（或在 `aster fix` 中提供自动修复）；
  3. 对被弃用的语法发出警告至少一个小版本。
- 进入 V1.0 后遵循语义化版本：主版本号变化才允许破坏兼容。
- 官方格式化器 `aster fmt` 是唯一的格式标准，不提供配置选项。

## 16. 诊断

- 所有错误与警告必须带有稳定错误码（见 03 §5 的编码规则）。
- 编译器输出的消息文本必须为英语（见 06 §3.0）。下表的中文说明仅供规范阅读，不是编译器输出。
- 错误码仅在本规范列出时有效。示例：

| 错误码 | 含义 |
|---|---|
| `E1000` | 未支持的语法 |
| `E1001` | 语法错误：缺少符号 |
| `E2010` | 循环依赖 |
| `E2020` | `app` 名称与清单不一致 |
| `E2301` | `match` 不完整 |
| `E3001` | 在非 `action` 中修改状态 |
| `E3010` | 在 `action` 中调用同步 I/O |
| `W1001` | 名称遮蔽 |
| `W1002` | 表达式结果未使用 |

## 17. 测试要求

每条语法与语义规则至少需要：

1. 一个正例测试：程序通过编译并输出期望结果。
2. 一个反例测试：程序报告指定错误码，且源位置正确。
3. 若规则与其他规则交互（如 `await` 与状态读取），增加交互测试。

规范的任何修改必须同步更新测试，否则不得合并。

## 18. 未纳入 V0.1 的内容

以下内容明确推迟，不得在 V0.1 实现：

- 泛型（用户自定义）、trait/接口、宏、反射。
- 闭包与高阶函数（`for` 与内建容器方法除外）。
- 字符串插值、运算符重载、位运算。
- 多窗口、多 `state` 块。
- `verify` 约束块（见 Q-07）。
- 语言自举。
- 非 Rust 的 FFI 语法（见 04 §4）。
